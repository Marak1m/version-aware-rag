# M5 plan: signals, inference, policy, clues (for review)

Status: for review, 2026-10-18. Nothing below is built. M5 is the handoff's milestone 6
("Signals, inference, policy"), with the decisions of 2026-10-15 and 2026-10-18 folded in. It
needs no model and no GPU: the extractor and the decision rule read only the query and context,
and the policy is exercised against the mock backends.

## Goal and acceptance

Handoff acceptance, unchanged:

1. Unit tests pass on at least 40 fixture snippets covering pins, code, keyword arguments,
   errors, migration messages, version guards and contradictions. This plan adds value-level
   signals, config keys and the weight-0 rule to that list.
2. Every seed clue, alone, makes the extractor infer its intended version (validation step 6,
   now enforced through `varag.pipeline.infer.check_clues`).
3. The `unsure` user arm returns two labelled answers.

Added by the user's decisions:

4. `freq="M"` passed to a resolved pandas callable is old-side evidence at keyword weight 3,
   `"ME"` new-side, from confirmed value rules; an unconfirmed value is no evidence.
5. A keyword declared on one side only whose other side takes `**kwargs` has weight 0 unless
   `data/rules` confirms it (`shared_unknown` in the diff since 2026-10-15); the extractor records
   it as an abstention.
6. Config keys are read wherever they appear: `class Config` bodies, `ConfigDict(...)` calls and
   `model_config` dict literals.
7. Behaviour concepts give no static signal and are reported separately.

## Signals

The handoff table, with the weights it gives. Each signal carries `source` (`query`, `context`,
`error`), `span` (line and column range), `symbol`, `side` and `weight`; `decisive` is a flag.

| Signal | Detection | Side | Weight |
| --- | --- | --- | --- |
| Version named in text | regex over query and context, the one the lint already uses, mapped to a side by major version | named | decisive |
| Requirement pin | `packaging` over requirement, pyproject, conda and `pip freeze` lines; exactly one side satisfies | that side | decisive |
| Migration message | `configs/migration_messages.yaml`, each pattern reproduced in one environment (existing rule) | emitting side | decisive |
| Error names a missing symbol or parameter | regex over the traceback (`has no attribute`, `unexpected keyword argument`, `cannot import name`, `PydanticUserError` kwarg messages), then inventory lookup; direction from the inventory | lacking side | 4 |
| Exclusive import | AST | having side | 4 |
| Exclusive symbol on a resolved receiver | AST, alias resolution (existing) | having side | 3 |
| Exclusive keyword on a resolved callable | AST, bound against both signatures (existing) | accepting side | 3 |
| **Exclusive argument value on a resolved callable** (new) | the keyword's value is a string or `None` constant that a confirmed value rule lists for that callable and parameter | the rule's side | 3 |
| **Config key** (new) | `class Config:` body assignments inside a `BaseModel` subclass; `ConfigDict(key=...)` keywords; `model_config = {"key": ...}` literal keys; each looked up as `pydantic.Config.<key>` | the bucket's side | 3 |
| Exclusive non-generic method on an unresolved receiver | `method_name_index` (existing) | having side | 1.5 |
| Deprecated-in-new usage on a resolved receiver | `deprecated_in_new` bucket (existing) | old, weakly | 1 |
| Generic method, `shared_unknown` callee, unconfirmed absorbed keyword, unconfirmed value | stoplist, inventory | neither | 0, logged as abstention |

Extraction rules from the handoff, all kept: a symbol named in an error is removed from the code
signals; score the call site, not the symbol; each distinct symbol, keyword, value or config key
counts once; a pin both sides satisfy is not a signal; usage inside a version guard counts for
neither side; receiver resolution follows aliases, constructor and reader assignments and
`BaseModel` subclasses, with name heuristics (`df`, `np`) at 1.5; parsing order is fenced blocks,
`ast.parse`, dedent and retry, line-by-line salvage, then a regex fallback at half weight.

Value signals, in detail:

- Only confirmed records count (`rules.value_rules(library)`). A value rule is matched on
  `(callable, parameter)` after receiver resolution and on the literal value; `anchored` rules
  also match `VALUE-SUFFIX` forms (`Q-JUN`, `A-DEC`). Positional values are not matched: the
  handoff scores keywords passed by name, and a positional `freq` is ambiguous.
- The side is the rule's `side`; the weight is 3, the keyword weight, as the user set.
- The old-side value of a two-directional pair (`"M"`) and its new-side counterpart (`"ME"`) are
  separate rules, so each is evidence for its own side; `"h"` (works on both) has no rule and no
  signal, while `"H"` is old-side evidence.
- The same matcher serves D-b: gold written `pandas.date_range(freq="M")` is parsed by
  `parse_gold`, step 4 treats it as old- or new-side evidence, step 7 links the pair through the
  rule, and `doc_conflict` counts a confirmed value pair as linked when both versions' owner
  chunks are present. The M6 guard flags a value the committed version rejects the same way it
  flags a keyword.

Config keys, in detail (D-f): a `class Config` body inside a class that subclasses `BaseModel`
(resolved, or heuristically by name when the base is unresolved, at 1.5) yields `pydantic.Config.<name>`
for each assignment; `model_config = {...}` with string keys yields the same; `ConfigDict(...)`
keywords likewise. `orm_mode` is old_only, `from_attributes` new_only, each weight 3. Keys in
`shared_same` (`extra`, `frozen`) give nothing. `ConfigDict` itself exists in pydantic 1.10 as a
TypedDict (it is `shared_unknown`), so the keys, not the class, carry the evidence.

## Decision rule

Exactly the handoff's, in `pipeline/infer.py`:

```
S[v] = sum of non-decisive weights for v; D[v] = any decisive signal for v
strong(v) = D[v] or S[v] >= tau_commit        # 3.0
weak(v)   = not D[v] and S[v] <= tau_noise    # 1.5
INFER(old) if strong(old) and weak(new); INFER(new) if strong(new) and weak(old)
CONTEXT_CONFLICT if neither side is weak; else UNCERTAIN
margin = S[old] - S[new], logged with D[old], D[new]
```

Thresholds come from `configs/experiment.yaml` and are frozen on dev clue instances (Part B
step 8). Two decisive signals on opposite sides are a `CONTEXT_CONFLICT` whatever the sums.
Weights are not tuned in M5; fitting them is L17 (v1).

`check_clues(concept)` (validation step 6): for each clue, run the extractor on the clue text
alone with an empty query and require `INFER(side)` for the clue's side; for each error clue,
re-run the clue's snippet in the target environment through the harness and require the recorded
traceback's last line to match. Returns `{"problems", "info"}` like step 7, with the decision and
margin per clue in `info`. The step fails on any miss; a clue is fixed or dropped, never the rule.

## Policy, questions and the simulated user

`pipeline/policy.py` implements the handoff's pseudocode as written, on top of the existing
`retrieve`, `doc_conflict`, `keep_version`, `dedupe` and `Backend`:

- `INFER(v)` commits; otherwise `doc_conflict` decides between answering once on the deduplicated
  set and asking. One question per instance.
- Question templates are the handoff's two, verbatim, with major versions from the manifest.
  `parse_version` reads a major version or "not sure" from the reply; anything else is unusable
  and falls to the "both" path.
- The simulated user is rule-based: `knows` answers "I'm on {library} {v*}." and `unsure` "I'm
  not sure."; either answers only when the question names the library or the word "version",
  otherwise "I'm not sure what you're asking." with `question_relevant: false`.
- Negative constraints: `unavailable_symbols(signals, v)` lists the error-named symbol and every
  other-version call, keyword, value or config key from the context, each with its replacement
  from `data/rules` (replacements, value rules) when known; the committed prompt adds one line
  per item.
- The "both" fallback makes two generation calls on version-filtered documents and returns two
  labelled blocks; `extract_code` already splits labelled blocks.
- Behaviour concepts: their gold symbols are shared, so code and value signals cannot point at a
  side; inference on their instances rests on pins, named versions, migration messages and error
  clues. Their trace records `behaviour: true`, and every report slices them apart
  (`by_exclusivity`, already in `run.json`); the guard never flags them and its precision and
  recall exclude them.

`traces.jsonl` gets, per instance: signals with spans and weights, `S` and `D` per side, the
margin, the decision and its reason, chunks kept and dropped, the question and reply, the
`question_relevant` flag, negative constraints sent, and (M6) guard activity.

## `make-error-clue`

`varag bench make-error-clue <concept> --target old|new`: runs a 5-to-15-line snippet that uses
the other version's API in the target environment, through the harness (same limits, stripped
environment), and writes `clues/<target>_error.txt` as the snippet, a separator, and the captured
traceback. The snippet is the author's; the command refuses a snippet whose traceback does not
name an exclusive symbol or parameter, or that names a version in prose (the lint exempts the
traceback, as decided on 2026-10-08). Each concept records the clue in `concept.yaml` with
`overlap`. Seed concepts get error clues in Part B step 7, when `make-error-clue` exists.

## Tests

At least 40 fixtures in `tests/fixtures/signals/`, each a snippet with the expected side, weights
and decision, grouped: pins (satisfied by one side, by both, conda, pyproject, freeze); named
versions; migration messages (one per pattern); errors naming symbols and keywords (direction
from the inventory, symbol removed from code signals); exclusive imports; exclusive symbols on
resolved and heuristic receivers; keywords (exclusive, confirmed absorbed, unconfirmed absorbed
at weight 0); values (`"M"` old, `"ME"` new, `"Q-JUN"` anchored, `"h"` none, positional ignored,
unconfirmed none); config keys in the three forms; deprecated-in-new at weight 1; version guards;
contradictions (`CONTEXT_CONFLICT`); the regex fallback at half weight. Plus: the decision rule on
synthetic scores at the thresholds; `check_clues` on the seed concepts (envs test); the policy
on the mocks (commit, no-conflict single answer, ask with each arm, "both" with two labelled
blocks); `make-error-clue` on np-001 in both directions (envs test).

## Out of scope

The blend guard's violation rule, repair prompt and acceptance check; the real client and cache;
baselines; leak audit and serving checks (M6, M7 and the GPU session). Weight fitting (L17).

## Decisions (settled by the user, 2026-10-18)

1. **Positional values are bound, not ignored.** A positional argument is bound to a parameter
   name through the resolved callable's signatures on both sides. A value rule applies when both
   versions put that parameter at the same position (`df.resample("M")` binds to `rule` on both).
   The binding is skipped when the positions differ or the argument falls into `*args`. Fixtures:
   `resample("M")` (old side), `resample("ME")` (new side), and `to_period("M")`, which gives no
   signal because periods still accept `"M"` in 3.0.6 (checked in the environments).
2. **Config keys under an unresolved `BaseModel` base count at 1.5**, like a name heuristic.
3. **`make-error-clue` refuses a traceback that names nothing exclusive.** A traceback counts as
   naming something exclusive if it names an exclusive symbol, an exclusive keyword, a value
   rejected by a confirmed value rule, or matches a migration message. Behaviour concepts get pin
   and code clues only; the clue-type rotation that balances pin, code and error is computed over
   the other concepts.
4. **An error that names a rejected value is negative evidence at weight 4**, like a missing
   symbol: "Invalid frequency: ME" means the installed version lacks `"ME"`, so it supports the
   side whose rules do not list that value. Fixtures cover `Invalid frequency: ME` (old side),
   `Invalid frequency: M` (new side) and `invalid unit abbreviation: T` (new side).
