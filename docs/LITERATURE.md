# Unstated library versions expose RAG's blind spot

No published work studies VA-RAG's joint setting: a library version that is not stated, retrieved documentation that mixes two incompatible versions, a clarify-or-answer decision, and execution of every answer in both pinned environments. Each ingredient has its own literature, and that literature supports the shape of the VA-RAG design while exposing specific weak points in it. Version-conditioned benchmarks state the version and the best models still solve only about half the problems (48–51% on GitChameleon 2.0); a version tag shown to the generator adds under one F1 point, while version-filtered documentation adds 4–14 ([GitChameleon 2.0](https://arxiv.org/html/2507.12367v2), [LibEvolutionEval](https://aclanthology.org/2025.naacl-long.348.pdf)). For 7B-class models, one outdated passage beside the current one produces 17–22% harmful answers even with timestamps and a "prefer current" instruction, and roughly one answer in five merges sources ([HoH](https://aclanthology.org/2025.acl-long.301.pdf), [AmbigDocs](https://arxiv.org/html/2404.12447v3)). Small models cannot decide from a prompt when to ask, so moving that decision into rules is well supported ([APA](https://arxiv.org/html/2404.11972v3)). A deterministic inventory guard reaches 100% precision on curated data, but version confusion concentrates in keyword arguments and behaviour changes that a symbol lookup does not see ([Khati et al.](https://arxiv.org/html/2601.19106v1), [LibEvoBench](https://arxiv.org/html/2606.25402v1)). On evaluation, a 60-concept, 240-instance benchmark can detect paired differences of roughly 8–16 percentage points, and vLLM by default loads the model repository's sampling configuration, which for Qwen2.5-Coder-7B-Instruct includes a repetition penalty of 1.1 ([Miller](https://arxiv.org/pdf/2411.00640), [vLLM CLI reference](https://docs.vllm.ai/en/latest/cli/serve/), [Qwen generation config](https://huggingface.co/Qwen/Qwen2.5-Coder-7B-Instruct/raw/main/generation_config.json)). The novelty claim rests on keyword search rather than an exhaustive citation crawl, and the figures in this report were transcribed through an automated page-reading tool, so table-level numbers need a spot-check against the PDFs before they are quoted in a paper.

## How far the numbers in this review can be trusted

The researchers read every source through a fetch-and-extract tool that summarises pages. They flag three classes of weaker evidence, and this report carries those flags next to the affected claims. First, some sources were read only as an abstract, an overview page, a README or slides; these are marked "abstract-level" or "secondary source" where used. Second, many venues were not confirmed on any opened page; the report names a venue only where a proceedings page was opened and otherwise says "arXiv preprint" or "venue unverified". Third, a few papers are internally inconsistent, and the report repeats the inconsistency instead of picking a value.

The negative findings carry a matching caveat. The claim that no one has studied VA-RAG's combined setting comes from keyword search across the five research strands; the Semantic Scholar citation API failed during the citation-trail step, and one possibly relevant paper, "Who Broke Me? Execution-Guided Repair of Behavioral Dependency Breaks" (arXiv 2610.09267), could not be opened and is known by title only. The researchers also did not verify the exact target versions named in the VA-RAG brief (pandas 3.0.6, NumPy 2.4.x, pydantic 2.13) against release pages; they confirmed that pandas 3.0.0 shipped on 21 January 2026 and that NumPy 2.5.0 is now listed, so NumPy 2.4 is no longer the newest line ([pandas 3.0.0 what's new](https://pandas.pydata.org/docs/whatsnew/v3.0.0.html), [NumPy release notes](https://numpy.org/doc/stable/release.html)).

## Roughly fifteen version benchmarks, and none withholds the version while mixing the docs

### Three benchmark families that never meet VA-RAG's setting

Version-conditioned code generation now has roughly fifteen benchmarks, and they fall into three families. The first states the version in the prompt and executes in one pinned environment. GitChameleon 2.0, published at ACL 2026, has **328 hand-written Python problems over 26 libraries**, pins the exact version in both the prompt and the validation environment, and ranks on hidden tests with 96.5% coverage while exposing only a short visible test for self-debugging ([ACL Anthology](https://aclanthology.org/2026.acl-long.2170/), [arXiv PDF](https://arxiv.org/pdf/2507.12367)). VersiBCB (ICSE 2026) attaches multi-library environment lists to BigCodeBench tasks and separates a Strict split, which allows only supported APIs, from a Lenient split that tolerates deprecated-but-working calls; the paper's instance counts do not reconcile (it reports "725 executable instances" and also 417 generation plus 416 migration items) ([VersiBCB](https://arxiv.org/html/2601.12262v1)). The second family mines large completion sets and scores them statically: VersiCode covers over 300 libraries with exact-match style metrics, LibEvolutionEval (NAACL 2025) scores F1 over called APIs, and LibEvoBench scores 125k instances against per-version compatibility matrices built from Sphinx inventories plus runtime introspection ([VersiCode](https://arxiv.org/html/2406.07411v2), [LibEvolutionEval](https://arxiv.org/html/2412.04478v1), [LibEvoBench](https://arxiv.org/html/2606.25402v1)). The third family hands the model an API update in context and tests whether it is used: CodeUpdateArena with 670 synthetic tasks and "When LLMs Lag Behind" with 270 real post-2023 updates ([CodeUpdateArena](https://arxiv.org/html/2407.06249v3), [Ashik et al.](https://arxiv.org/html/2604.09515v1)).

Only two works execute one answer under more than one library version. CodeUpdateArena's UPass counts a solution only if it passes with the updated function and fails some test with the old one, and the 2026 Qiskit benchmark runs every snippet in all three pinned environments regardless of the prompted version, adding a soft-fail class for deprecation warnings ([CodeUpdateArena](https://arxiv.org/html/2407.06249v3), [quantum-api-drift](https://arxiv.org/html/2607.04072)). Both still tell the model the version or the update. The Qiskit matrix shows why cross-environment execution is informative: one model prompted for v1.3 scored 0.693 in the v2.0 environment against 0.253 in the prompted one, which the authors read as ignoring the version anchor ([quantum-api-drift](https://arxiv.org/html/2607.04072)).

### What the benchmarks say about model behaviour

Stating the version is not enough. LibEvoBench finds that adding `# requires:lib==ver` yields no measurable gain for any model family while adding a docstring gives a consistent 10–20 point gain, and calls current models "largely version-oblivious"; its models are frontier and large open models, not 7B ([LibEvoBench](https://arxiv.org/html/2606.25402v1)). LibEvolutionEval's version comment moves StarCoder2-7B from 68.8 to 69.3 F1 on PyTorch, against 73.3 with version-specific retrieval ([LibEvolutionEval](https://arxiv.org/html/2412.04478v1)). On GitChameleon 2.0, with the version always stated, enterprise models sit in a **48–51% band** ([GitChameleon 2.0](https://arxiv.org/html/2507.12367v2)).

Context, not recency, decides which version's API a model emits. Wang et al. measured deprecated-API usage of **70–90% when the surrounding code already used the old API and 9–18% in up-to-date contexts**, across seven models; the venue (ICSE 2025) comes from a programme page seen in search results, not opened ([Wang et al.](https://arxiv.org/html/2406.09834v3)). The direction of bias is not uniformly "older": accuracy declines for recent release years in GitChameleon v1, VersiCode and LibEvoBench, but GitChameleon 2.0 reports no significant release-year effect and the Qiskit middle version is hardest for every model ([GitChameleon v1](https://arxiv.org/html/2411.05830v1), [arXiv PDF 2507.12367](https://arxiv.org/pdf/2507.12367), [quantum-api-drift](https://arxiv.org/html/2607.04072)). When models choose a version themselves, the median choice lags their knowledge cutoff by 9 to 31 months ([PinTrace](https://arxiv.org/html/2605.06279v1)). The researchers' reading is that no opened paper ties training-corpus frequency of old versus new forms causally to output choice; what is supported is that accuracy is frequency-dependent and that prompt context dominates.

Blending has been observed but barely measured. In "When LLMs Lag Behind", under the best configuration, 195 failure-to-adopt cases split into omission 42.1%, old-API usage 16.4% and **mixed old/new usage 12.3%**; that is a share of a failure subset under single-version documentation, not a rate over all outputs ([Ashik et al.](https://arxiv.org/html/2604.09515v1)). Bae et al. report that an 8B Llama model used both the deprecated and the replacement function in about 14% of replacement-conflict cases and kept its parametric pattern in roughly 76–83% of cases despite an explicit deprecation notice; these figures come from an overview page and need checking against the PDF ([Bae et al.](https://www.alphaxiv.org/abs/2510.19116)).

### Which methods moved the numbers

Execution feedback is the largest lever reported. Self-debugging against visible-test traces on GitChameleon 2.0 raises hidden-test success by +11.3 to +33.9 points (GPT-4.1-mini 44.2→68.0, Llama 3.1 30.2→52.1), more than retrieval's +4.3 to +10.0 over a 536-document API corpus at k=3 ([arXiv PDF 2507.12367](https://arxiv.org/pdf/2507.12367)). RustEvo² shows the same ordering for post-cutoff APIs: 34.9% with no information, 48.4% with RAG, 57.7% with the API information given directly ([RustEvo²](https://arxiv.org/html/2503.16922v1)). Ashik et al. find documentation raises adoption from 74.64% to 92.87% but executability only from 42.55% to 66.36%, with self-reflection adding 11.33 points on top ([Ashik et al.](https://arxiv.org/html/2604.09515v1)).

Structured documentation beats raw documentation. In DepRepair, raw release notes and API diffs lowered repair rates (GPT-5.5 82.1%→74.7%; a Claude Code agent 81.1%→57.9%), while distilling the same evidence into migration rules with a usage locator raised them to 89.5% ([DepRepair](https://arxiv.org/html/2607.17957)). Selective retrieval beats always-retrieve: CloudAPIBench's DAG++ retrieves only when the generated API name is missing from an index or token confidence is low, lifting CodeGemma-7B's average valid-invocation rate from 46.95% to 63.34% where unconditional retrieval reached 53.86% and cut high-frequency validity from 87.80% to 61.95% ([Jain et al.](https://arxiv.org/html/2407.09726)). Parameter-level approaches are the least reliable: after model editing, correct adoption of the new API was about 6% in one robustness study, and fine-tuning on update docstrings alone did not help in CodeUpdateArena ([Chhetri et al.](https://arxiv.org/html/2511.03182v1), [CodeUpdateArena](https://arxiv.org/html/2407.06249v3)).

The researchers' inference from this ranking matters for VA-RAG: the strongest lever, execution in the target environment, is unavailable at answer time because the target environment is exactly what is unknown. That strengthens the case for explicit version inference and for asking.

## Mixed evidence gets resolved by priors, repetition and position, not by version tags

### A version conflict is under-specification, not falsehood

The standard taxonomy (Xu et al., EMNLP 2024) splits knowledge conflicts into context-memory, inter-context and intra-memory, and already names outdated information as a cause of inter-context conflict that needs separate analysis ([Xu et al.](https://arxiv.org/html/2403.08319v2)). Cattan et al. attach an expected behaviour to each cause: consolidate complementary information that arises from an under-specified query, prioritise current information under a freshness conflict, disregard misinformation ([Cattan et al.](https://arxiv.org/html/2506.08500v2)). No taxonomy the researchers found treats "both documents valid, each under a different environment" as its own category. Their mapping is that a two-version documentation conflict is "complementary information" until the version is known and a freshness-type conflict afterwards, with the twist that the applicable document may be the older one, so recency heuristics point the wrong way for users pinned to old versions.

### What decides which document a model follows

Four content cues dominate, and none correlates with the user's installed version. Agreement with parametric memory: with one supporting and one conflicting passage, Llama2-7B follows memory in 58.4% of PopQA cases (the source table was partly garbled in extraction, so cells are approximate) ([Xie et al.](https://arxiv.org/html/2305.13300v4)). Repetition: a low-credibility source repeated twice beats a single government source for all 13 open models tested, and prompting to ignore repetition does not restore consistency ([Schuster et al.](https://arxiv.org/html/2601.03746v3)). Query similarity: paragraph-to-query embedding similarity correlates strongly with which paragraph wins, and style-level credibility edits are neutral to negative ([Wan et al.](https://arxiv.org/html/2402.11782v2)). Position: order alone swings Llama2-7B's memorisation ratio from 33.3 to 82.8, and in the temporal HoH benchmark Qwen2.5-7B does best with oldest-first ordering while Llama-3.1-8B does best newest-first ([Xie et al.](https://arxiv.org/html/2305.13300v4), [HoH](https://aclanthology.org/2025.acl-long.301.pdf)).

Temporal conflict is the closest analogue to version conflict, and the results for small models are poor. HoH (ACL 2025) gives each document's last-modified time, today's date, a "prioritise current" instruction and an "Unsure" option; **one outdated passage beside the current one still yields harmful answers 17.20% of the time for Llama-3.1-8B and 21.68% for Qwen2.5-7B**, and 71–80% for the same two models when the outdated passage stands alone ([HoH](https://aclanthology.org/2025.acl-long.301.pdf)). A 2026 preprint on stale-document poisoning finds one outdated document flips about 30–37% of previously correct answers for 7–8B models; software was the most resistant of four domains (0.17–0.35), on only 60 items ([Ahmed et al.](https://arxiv.org/html/2609.31342)). Retrieval cannot fix this by relevance: bge-m3's top-5 hit rate is 0.7312 for current passages and 0.5507 for outdated ones, and among negatives that re-rankers place above the correct passage, 84–98% are outdated versions ([HoH](https://aclanthology.org/2025.acl-long.301.pdf), [FRESCO](https://arxiv.org/html/2604.14227)).

### Merging is measured, and metadata only works when something acts on it

AmbigDocs gives the nearest published metric to a version-blend rate. With one gold document per same-named entity, **21.7% of Llama2-7b answers and 18.9% of Mistral-7b answers are "merged"**: several answers with no entity attached. Few-shot examples do not reduce Llama2-7b's share, and entity-answer recall falls from 0.762–0.841 with one document to 0.244–0.473 with several ([AmbigDocs](https://arxiv.org/html/2404.12447v3)). In two-passage factual conflicts the more common failure is silently picking one side, 81–94% of answers in WikiContradict ([WikiContradict](https://arxiv.org/html/2406.13805v1)).

Displayed metadata shifts behaviour weakly; metadata used as a filter shifts it strongly. A version comment adds +0.2 to +1.0 F1 where version-matched documentation adds +4.5 to +14.2 ([LibEvolutionEval](https://aclanthology.org/2025.naacl-long.348.pdf)). VersionRAG's version-constrained retrieval lifts version-specific accuracy from 55% to 100% with a 70B model, but the gain vanishes with Llama 3 8B (40% to 40%), whose query-intent classification is only 76% accurate; VersionRAG also does not say what happens when the query names no version ([VersionRAG](https://arxiv.org/html/2510.08109v1)). The researchers infer that version extraction should happen outside the small model, by rules. Wrong metadata reverses the benefit: incorrect dates make a recency-aware re-ranker favour outdated evidence ([Ahmed et al.](https://arxiv.org/html/2609.31342)). The one display-side intervention with a near-ceiling effect is an explicit validity boundary stated in the context, and that result holds mainly for 70B-class models; the small-model effect is described only as modest ([Ahmed et al.](https://arxiv.org/html/2609.31342)).

Conflict-aware instructions help where a conflict exists and cost where none does. An instruction to consider conflicting information raises correct handling for Mistral-7b from 2.1% to 20.8% ([WikiContradict](https://arxiv.org/html/2406.13805v1)). FaithEval's conflict instruction lowers accuracy on normal contexts, a contradiction hint in the Ragability benchmark significantly reduces performance on non-contradictory contexts (abstract-level), and when asked to look for contradictions GPT-4 confirmed only 44% of conflict-free passage pairs as conflict-free ([FaithEval](https://arxiv.org/html/2410.03727v3), [Ragability](https://aclanthology.org/2026.lrec-1.182/), [WikiContradict](https://arxiv.org/html/2406.13805v1)). Contrastive decoding is a poor fit: it targets context-versus-memory conflict, needs two passes, and static context-aware decoding costs LLaMA2-7B 5.5 EM points on non-conflicting inputs ([COIECD](https://arxiv.org/pdf/2402.11893)). Multi-agent and consolidation pipelines such as MADAM-RAG and Astute RAG were validated on 70B-class or frontier models only ([Wang et al.](https://arxiv.org/html/2504.13079v2), [Astute RAG](https://arxiv.org/pdf/2410.07176)).

For unresolvable conflict the literature converges on type-dependent behaviour: present every valid answer paired with what it belongs to, ask when the conflict comes from an under-specified query, and never silently pick or merge ([AmbigDocs](https://arxiv.org/html/2404.12447v3), [Liu & Roth](https://arxiv.org/html/2504.19472), [Wan et al.](https://arxiv.org/html/2402.11782v2)). No opened paper evaluates a clarifying question as the response to inter-context conflict in RAG; the recommendation appears only as discussion.

## Small models cannot be trusted to decide when to ask

### Under-asking by default, over-asking when pushed

Instruction-tuned models guess one interpretation. On deliberately broken HumanEval specifications, more than 60% of code-LLM responses still generate code instead of asking, and coding agents "almost never interact" without explicit prompting ([HumanEvalComm](https://arxiv.org/html/2406.00215), [Ambig-SWE](https://arxiv.org/html/2502.13069)). For 7B-class models the evidence is direct: direct and self-ask prompting give **0.00 ambiguity-detection F1 for Mistral 7B and LLaMA2 13B**, while ambiguity-aware prompts over-predict clarification ([APA](https://arxiv.org/html/2404.11972v3)). Prompted detection swings by model: Llama 3.1 70B has a false-positive rate of 0.93 and Qwen 3 Coder never asks under any prompt ([Ambig-SWE](https://arxiv.org/html/2502.13069)). Contradiction is the category models are worst at spontaneously asking about: ClarifyCoder's communication rate is 48.78% on inconsistency against 76.22% on incompleteness ([ClarifyCoder](https://arxiv.org/html/2504.16331)).

Over-asking has a measured price. The multi-round Okanagan agent, built to ask, scores 27.45% Pass@1 on original, unmodified HumanEval problems against 65.58% for plain ChatGPT; the same paper's abstract and introduction disagree on its headline gains ([HumanEvalComm PDF](https://arxiv.org/pdf/2406.00215)). Asking on every requirement underperforms selective asking: 69.94 versus 75.75 average Pass@1 for GPT-4 in ClarifyGPT ([ClarifyGPT](https://ar5iv.labs.arxiv.org/html/2310.10996)). Most code papers never test their asking policy on clean inputs at all.

The triggers that work sit outside a plain prompt: behavioural disagreement among sampled programs (ClarifyGPT, SpecFix), a trained gate, or a separate detector agent ([ClarifyGPT](https://ar5iv.labs.arxiv.org/html/2310.10996), [Ask or Assume](https://arxiv.org/html/2603.26233v2)). Two results support checking explicit context evidence first. SpecFix's ablation finds alignment with examples already in the prompt worth +4.2% Pass@1 against +0.9% for entropy reduction alone, and Ask-before-Plan's clarification agent using conversation plus environment observations reaches 99.4 micro accuracy against 76.8 for the best conversation-only prompted baseline ([SpecFix](https://arxiv.org/html/2505.07270), [Ask-before-Plan](https://arxiv.org/html/2406.12639)). No clarification benchmark for code includes library version as an ambiguity category; ClarifyCodeBench's ten categories and AssumptionMiner's six do not ([ClarifyCodeBench](https://arxiv.org/html/2607.00711), [AssumptionMiner](https://arxiv.org/html/2607.22898v1)). The adjacent fact is that library version constraints appear in only 9% of code-related developer–ChatGPT conversations and are mostly introduced by users (abstract-level) ([Raj & Costa](https://arxiv.org/abs/2401.16340)).

### Decision rules and how to report them

Cost-sensitive rules now beat tuned confidence thresholds. The Value-of-Information framework (ACL 2026) asks the question with the highest expected value net of a per-question cost and otherwise commits; it matches or exceeds the best grid-searched baseline in 18 of 20 conditions, and at high question cost never asking wins ([Dong et al.](https://arxiv.org/html/2601.06407v1)). Zhang et al. label ties between asking and answering in favour of answering ([Zhang et al.](https://arxiv.org/html/2410.13788)). The researchers' inference for VA-RAG is that the hidden variable is binary, so the rule can be computed exactly: ask when the probability of the minority version times the loss from a wrong-version answer exceeds the cost of a question, and never ask when the API behaves identically in both versions.

The abstention literature supplies the reporting standard: count both error directions, report coverage with the accuracy-coverage trade-off, and prefer threshold-free curves such as risk-coverage and AUROC over a single operating point ([Wen et al.](https://arxiv.org/html/2407.18418), [Traub et al.](https://arxiv.org/abs/2407.01032)). ClarifyCodeBench's Optimal Round Adherence penalises both premature coding and over-questioning ([ClarifyCodeBench](https://arxiv.org/html/2607.00711)).

### Simulated users inflate results unless audited

A simulated user that always knows its version is an upper bound. TiCoder's authors say so of their own rule-based oracle ([TiCoder](https://arxiv.org/html/2404.10100)). LLM simulators leak: HumanEvalComm's audit found the evaluator supplied the missing information even when the model asked no question in **32.5–40.7% of cases for four of the code models** ([HumanEvalComm PDF](https://arxiv.org/pdf/2406.00215)). Real users are less cooperative than simulators: on τ-bench retail, agent success ranged 67.0–75.9% across simulator models but was 45.2% with real participants, and a 451-participant study describes simulators as creating an "easy mode" (abstract-level for the latter) ([Lost in Simulation](https://arxiv.org/html/2601.17087v2), [Sim2Real](https://arxiv.org/abs/2603.11245)). Current practice restricts the simulator to answering only what was asked from a fixed source, with an explicit "I don't have that information" path ([Ambig-SWE](https://arxiv.org/html/2502.13069)). The researchers found no study measuring how often real developers can state their installed library version when asked.

On question design, specific closed-form questions that present the candidates as options outperform generic ones. In 74.6M Bing impressions, specific templates drew far more engagement than generic ones, and a single clarification question listing interpretations as options was unanimously preferred 23 times against 5 for listing all answers in a 100-question study ([Zamani et al.](https://ar5iv.arxiv.org/html/2006.00166), [Lee et al.](https://ar5iv.labs.arxiv.org/html/2305.13808)). For 7B and 13B models, fixed clarification phrases generally beat generated ones, which supports VA-RAG's templated question ([APA](https://arxiv.org/html/2404.11972v3)). The alternative to asking is the conditional, all-branches answer; identifying conditions before answering raised Qwen2.5-7B's answer score from 0.13 to 0.30 in CondAmbigQA ([CondAmbigQA](https://arxiv.org/html/2502.01523)). No head-to-head of "ask", "answer both branches" and "assume and state" exists on a code benchmark.

## Static guards are precise but miss parameters, receivers and behaviour

### Where API errors come from

Invalid API use tracks API frequency. On CloudAPIBench, 7B-class models produce valid calls for 86–89% of high-frequency APIs and 9–13% of low-frequency ones ([Jain et al.](https://arxiv.org/html/2407.09726)). For StarCoder-7B on Python, non-existent methods are 40.9% of method-level failures and non-existent parameters 31.3% of parameter-level failures, while "intent misuse" (a real API that is the wrong one) is 30.4% of method failures and invisible to any existence check ([Zhuo et al.](https://arxiv.org/html/2503.22821)). For version confusion specifically, LibEvoBench finds anachronistic predictions negligible at API-name level but **6–14% at parameter level on signature recall**, and wrong parameters lead execution failures under API updates at 26.6% ([LibEvoBench](https://arxiv.org/html/2606.25402v1), [Ashik et al.](https://arxiv.org/html/2604.09515v1)). A guard that checks only called symbol names therefore misses most version confusion.

Small models are poor judges of their own hallucinations. Hallucination-existence recognition was 70.36% for Code Llama and 46.72% for DeepSeek-Coder in one taxonomy study, with zero self-mitigation for both ([Liu et al.](https://arxiv.org/html/2404.00971v1)). Hallucinations are also systematic: 43% of hallucinated package names recurred in all ten re-runs, so re-sampling without changing the conditioning is a weak repair ([Spracklen et al.](https://arxiv.org/html/2406.10279)).

### What deterministic detection achieves

Khati et al. (FORGE 2026) built almost exactly VA-RAG's guard: a knowledge base made by importing each library and enumerating public callables, keyed to `__version__`, plus an AST pass over imports, aliases and call sites. On 200 curated GPT-5 snippets it reached **precision 100%, recall 87.6%**, with pandas the weakest library at 85.1% detection, and contextual mismatches detected only 33.3% of the time; the paper describes no receiver inference and no parameter check, and the samples are curated, not a natural distribution ([Khati et al.](https://arxiv.org/html/2601.19106v1)). Off-the-shelf type checkers catch 14–85% of library hallucinations, with a manually estimated ceiling of 48.5–77% for what any static method could catch ([Miranda-Pena et al.](https://arxiv.org/html/2604.07755v1)). Receiver attribution is the hard part: Jedi infers 0 of 88 parameter types and Pyright 8 of 88 on a micro-benchmark, while PyCG's assignment-graph tracking reaches about 99.2% precision at 69.9% recall ([TypeEvalPy](https://www.arxiv.org/pdf/2312.16882v1), [PyCG](https://ar5iv.labs.arxiv.org/html/2103.00587)). Ding et al. add a cheap precision device: run the checker on the context alone and on context plus completion, and count only errors the generation introduces; they also find an error class present in the prompt is 7–200 times more likely to appear in the output ([Ding et al.](https://arxiv.org/html/2306.03203)). The researchers found no published precision or recall for a static version-inconsistency detector on natural LLM output; this is an open niche.

### Prevention and repair

Constrained decoding is not supported for Python data-science code. Monitor-guided decoding raises Java compilation rates by 18.5–24.7% relative and type-constrained decoding more than halves TypeScript compilation errors, but the one Python grammar experiment lowered pass rates (8.9 to 6.5 on DS-1000), and a 2026 preprint shows an incomplete constrainer can cut functional correctness by up to 97% (abstract-level) ([Agrawal et al.](https://arxiv.org/html/2306.10763), [Mündler et al.](https://arxiv.org/html/2504.09246), [Miranda-Pena et al.](https://arxiv.org/html/2604.07755v1), [Biagiola et al.](https://www.alphaxiv.org/abs/2606.21619)). The narrow form that works is prefix forcing: Wang et al.'s ReplaceAPI truncates at the deprecated call, forces the replacement's tokens and lets the model regenerate the arguments, fixing 85.2–99.6% of cases across open models, against 25.7–97.2% for a prompt-only instruction naming the replacement (95.5% for CodeLlama-7b) ([Wang et al.](https://arxiv.org/html/2406.09834)).

Repair loops pay off in the first round and are only as good as their feedback. De-Hallucinator, CoCoGen and Self-Debugging all show first-iteration gains dominating ([De-Hallucinator](https://arxiv.org/html/2401.01701), [CoCoGen](https://aclanthology.org/2024.findings-acl.138.pdf), [Chen et al.](https://arxiv.org/html/2304.05128)). CoCoGen's ablation shows error message plus retrieved relevant context (44.45–46.58 Pass@10) beating compiler feedback alone (40.43–41.78) ([CoCoGen](https://aclanthology.org/2024.findings-acl.138.pdf)). Wrong verdicts cause harm, and one result names VA-RAG's model: with self-generated tests, **Qwen2.5-Coder-7B-Instruct falls from 81.7 to 78.0 on HumanEval+ after one self-debugging round**, and detailed failure feedback does worse than a bare pass/fail label ([Chen et al., ACL 2025](https://aclanthology.org/2025.acl-long.881.pdf)). A single regeneration triggered by a high-precision deterministic guard fits this evidence; a guard that fires on generic method names would reproduce the harm.

### What documentation to retrieve and how much

Documentation helps most where the prior is weakest. Qwen2.5-Coder-7B-Instruct goes from 0.1182 to 0.3727 on Polars with BM25 top-5 documents, and from 0.5612 to 0.7410 on pandas; supplying the target document alone beats top-5 by 5–17 points for this model (derived by the researchers), so distractors cost a 7B model measurably ([Chen et al.](https://arxiv.org/pdf/2503.15231)). Compliance is much weaker when a document contradicts a memorised API: prepending the update documentation moves CodeLlama's UPass@1 only from 4.4 to 6.7 in CodeUpdateArena ([CodeUpdateArena](https://arxiv.org/html/2407.06249)). VA-RAG on pandas, NumPy and pydantic sits mostly in this second regime, which is why a post-hoc guard is justified on top of retrieval.

Content matters more than volume. Removing example code from documentation costs Qwen-7B 67% relative; a wrong API name inside example code costs it 37%, against 3–8% for the same error in prose; and models copy examples even when they do not fit the task ([Chen et al.](https://arxiv.org/pdf/2503.15231)). Jain et al. find the signature is the component that drives valid invocation (41.80 base, 86.82 with signature, 88.75 with the full 685-token document) ([Jain et al.](https://arxiv.org/html/2407.09726)). The two results use different metrics and are compatible. On quantity, k=5 chunks of 200–800 tokens is best in most CodeRAG-Bench settings and k=3 beats k=1 on GitChameleon 2.0 ([CodeRAG-Bench](https://arxiv.org/html/2406.14497), [GitChameleon 2.0](https://arxiv.org/html/2507.12367)). On the retriever, BM25 reaches recall@5 of 0.72–0.94 when the query is code, against 0.21–0.72 for a dense embedder, but collapses on natural-language queries (NDCG@10 of 5.2 on DS-1000 against 19.3 for a dense model) ([Chen et al.](https://arxiv.org/pdf/2503.15231), [CodeRAG-Bench](https://arxiv.org/html/2406.14497)).

## Environment-inference tools solve constraints or execute; none calibrates mixed evidence

### How software engineering infers environments

Dependency-inference tools share one design: a pre-built knowledge base mapping importable resources or API names to packages and version ranges, followed by constraint solving. SnifferDog (ICSE 2021 per a programme page not opened) is the closest prior art to VA-RAG's inventory: an API bank of 488 libraries and 1,013,718 APIs, with import-flow analysis for re-exports; 98.8% of 166 manually checked APIs were correct and 83.52% of known-executable notebooks ran after restoration ([SnifferDog](https://arxiv.org/abs/2103.02959)). Execution-feedback loops beat static lookup on the same 2,891 hard gists: PLLM fixed 1,583, ReadPyE 1,365 and PyEGo 1,302 ([PLLM](https://arxiv.org/html/2501.16191v2)). ReadPyE's own abstract reports 79.75% on single-file snippets, which the researchers could not reconcile with the 47% re-run figure because they read the abstract only ([ReadPyE record](https://api.openalex.org/works/doi:10.1109/TSE.2023.3346474)). No tool in this family reports precision for the binary question "old or new major version?", and the researchers found **no tool that fuses pins, imports, API usage and error text with a calibrated probabilistic model**. Published combiners are hard constraint solving, vote-ratio confidence, or execution as arbiter ([PCREQ](https://arxiv.org/pdf/2508.02023), [Decide](https://ar5iv.labs.arxiv.org/html/2308.13276), [V2](https://arxiv.org/abs/1909.06251)).

Two findings bear directly on VA-RAG's rule-based extractor. PCART's compatibility model says evidence depends on the call site: a renamed parameter breaks only keyword passing, a removal breaks only if the argument is passed, and changes behind `*args/**kwargs` are treated as compatible; its detection F1 is 96.49% in the paper body and 96.51% in the abstract ([PCART](https://arxiv.org/html/2406.03839)). Ruff's NPY201 rule suppresses findings inside `try/except` blocks that fall back to the new name, recognising deliberately portable code ([ruff source](https://raw.githubusercontent.com/astral-sh/ruff/main/crates/ruff_linter/src/rules/numpy/rules/numpy_2_0_deprecation.rs)).

### Error messages are strong evidence with ambiguous direction

API-evolution failures surface mostly as AttributeError (48.1%), TypeError (31.4%) and ImportError (14.2%); these percentages come from the authors' slides, not the paper ([Zhang et al. slides](https://cse.sustech.edu.cn/faculty/~liuyp/files/SANER2020-slides.pdf)). Direction is not given by the exception type: in a study of 446 deep-learning dependency bugs, backward incompatibility accounts for 22.6% and forward incompatibility for 17.0%, and 50.9% of bugs are exposed in a different dependency from the one that introduced them ([Huang et al.](https://ar5iv.labs.arxiv.org/html/2207.10347)). The exceptions are library-authored migration strings that only the new version can emit: NumPy 2's "`np.{attr}` was removed in the NumPy 2.0 release" and pydantic 2's `PydanticImportError` "has been removed in V2" ([numpy/__init__.py](https://raw.githubusercontent.com/numpy/numpy/main/numpy/__init__.py), [pydantic/_migration.py](https://raw.githubusercontent.com/pydantic/pydantic/main/pydantic/_migration.py)). The researchers found no study measuring "error message implies version X" as a classifier.

### What breaking-change detectors see, and what `inspect` misses

AexPy (ISSRE 2022) extracts APIs by dynamic import with static type enrichment and reports 86.9% recall on 61 known breaking changes and 93.5% precision on 405 detected changes (abstract-level) ([AexPy abstract record](https://api.semanticscholar.org/graph/v1/paper/DOI:10.1109/ISSRE55969.2022.00052?fields=title,abstract,authors,venue,year,externalIds,openAccessPdf)). Griffe analyses sources statically first, names twelve breakage kinds and warns that several "may not" raise immediately ([griffe docs](https://mkdocstrings.github.io/griffe/guide/users/checking/)). No Python tool handles behaviour changes; a 2026 systematic review of 97 studies calls detection approaches "accurate for syntactic breaks" with "limited coverage of behavioral ones" (abstract-level) ([Chen et al.](https://arxiv.org/abs/2605.24397)). Behaviour changes are not rare: about 20% of post-upgrade runtime failures in REQBench are API-body issues, against 61% API-name issues ([PCREQ](https://arxiv.org/pdf/2508.02023)).

The documented pitfalls of `inspect`-based extraction map one-to-one onto VA-RAG's three libraries. C-implemented callables raise `ValueError` on `inspect.signature` ([Python inspect docs](https://docs.python.org/3/library/inspect.html)). NumPy imports `linalg`, `fft`, `random` and other submodules lazily through a module `__getattr__`, and its `__dir__` hides some reachable members ([numpy/__init__.py](https://raw.githubusercontent.com/numpy/numpy/main/numpy/__init__.py)). **Pydantic V1-style methods (`dict()`, `json()`, `parse_obj()`, `copy()`) still exist on V2's `BaseModel` and only emit a `DeprecationWarning`**, so an existence diff files them under "same" ([Pydantic migration guide](https://pydantic.dev/docs/validation/latest/get-started/migration/)). Pandas 3.0 changed `__module__` to point at public modules, so an inventory keyed by `__module__` yields spurious "moved" symbols between 1.5 and 3.0 ([pandas 3.0.0 what's new](https://pandas.pydata.org/docs/whatsnew/v3.0.0.html)).

Machine-readable ground truth exists for names and signatures: ruff's NPY201 table of about 70 NumPy names with a backwards-compatibility flag, NumPy's `_expired_attrs_2_0.py`, and pydantic's `_migration.py` with about 200 removed names ([ruff source](https://raw.githubusercontent.com/astral-sh/ruff/main/crates/ruff_linter/src/rules/numpy/rules/numpy_2_0_deprecation.rs), [numpy/_expired_attrs_2_0.py](https://raw.githubusercontent.com/numpy/numpy/main/numpy/_expired_attrs_2_0.py), [pydantic/_migration.py](https://raw.githubusercontent.com/pydantic/pydantic/main/pydantic/_migration.py)). Pandas has only prose release notes. The pandas 1.5→3.0 pair spans two major releases, and the 3.0 notes cover only 3.0 changes; the researchers could not confirm items such as the `DataFrame.append` removal or the `'M'`→`'ME'` alias change in the pages they read, so the 2.0 and 2.x notes must be mined separately. None of these rule sets encodes behaviour changes such as pandas Copy-on-Write and the `str` dtype, NumPy NEP 50 promotion, or pydantic's `Optional` semantics ([pandas 3.0.0 what's new](https://pandas.pydata.org/docs/whatsnew/v3.0.0.html), [NumPy 2.0 migration guide](https://numpy.org/doc/stable/numpy_2_0_migration_guide.html), [Pydantic migration guide](https://pydantic.dev/docs/validation/latest/get-started/migration/)).

## A 240-instance benchmark detects 8–16 point differences, and serving defaults can skew them

### Test adequacy cuts both ways

Weak tests inflate scores: extending HumanEval's tests 80-fold cut pass@k by up to 19.3–28.9% and changed model rankings, and 31.08% of passed SWE-bench patches were "suspicious" because tests were too weak ([EvalPlus](https://arxiv.org/html/2305.01210v3), [SWE-Bench+](https://arxiv.org/abs/2410.06992)). Strict tests deflate them: OpenAI's 2026 audit found 35.5% of audited SWE-bench Verified problems had "narrow" tests enforcing specific implementation details ([OpenAI](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/)). SWE-bench's admission rule keeps a task only if at least one test goes from failing to passing under the reference patch ([SWE-bench](https://arxiv.org/html/2310.06770v3)). For VA-RAG the two risks have specific shapes: a test that never exercises the version-sensitive behaviour passes in both environments and inflates "portable", and a test that asserts a particular API rejects legitimate portable answers. Infrastructure failures need their own bucket; HumanEval's README warns that out-of-memory conditions "may cause some correct programs to fail" ([human-eval README](https://github.com/openai/human-eval)).

Pinned environments must be complete. Pandas 3.0 requires Python 3.11+ and NumPy ≥1.26.0, so a pandas 1.5.3 versus 3.0.x pair implies different NumPy and possibly different interpreter versions ([pandas 3.0.0 what's new](https://pandas.pydata.org/docs/whatsnew/v3.0.0.html)). Version benchmarks also under-represent the hardest category: behavioural changes score 38.0% in RustEvo² against 58.2% for signature changes, and they are the rarest type in GitChameleon ([RustEvo²](https://arxiv.org/html/2503.16922v1), [GitChameleon v1](https://arxiv.org/html/2411.05830v1)).

### Statistical power for 60 concepts

Miller's guidance is to report standard errors clustered on related question groups, compare systems on paired per-item differences, and state the minimum detectable effect; clustered standard errors can be over three times the naive ones, and detecting a 3-point difference at 80% power needs about 969 independent questions ([Miller](https://arxiv.org/pdf/2411.00640)). Bowyer et al. argue that below a few hundred datapoints CLT intervals dramatically underestimate uncertainty and that only Wilson and Bayesian intervals achieve nominal coverage at small N ([Bowyer et al.](https://arxiv.org/html/2503.01747)). McNemar's test fits paired binary outcomes ([Dror et al.](https://aclanthology.org/P18-1128.pdf)).

The table below is the researchers' own calculation, not a published result. It applies Miller's formula at α = 0.05 and 80% power with deterministic decoding, treats the variance of the paired difference as approximately the discordant-pair rate, and handles clustering with the textbook design effect 1 + (m−1)ρ for four instances per concept, a formula the researchers did not source.

| Discordant rate | ρ = 0 (n_eff 240) | ρ = 0.25 (n_eff 137) | ρ = 0.5 (n_eff 96) | ρ = 1 (n_eff 60) |
|---|---|---|---|---|
| 0.10 | 5.7 pp | 7.6 pp | 9.0 pp | 11.4 pp |
| 0.20 | 8.1 pp | 10.7 pp | 12.8 pp | 16.2 pp |
| 0.30 | 9.9 pp | 13.1 pp | 15.7 pp | 19.8 pp |

On these assumptions the current design detects roughly an 8–16 point paired difference in a typical case and nothing under about 5 points; a single system's accuracy carries a 95% half-width between about ±6 and ±12 points depending on within-concept correlation. More concepts, not more instances per concept, is the lever. No source gives an empirical within-concept correlation for version tasks; it must come from pilot data. Prompt wording is a confound of the same order: across 6.5M instances, a single word change moved one model by +46% on average, and model rankings shifted across paraphrases ([Mizrahi et al.](https://arxiv.org/html/2401.00595v3)). The researchers did not open a source on Holm correction; its use in VA-RAG is standard but uncited here.

### Reproducibility with vLLM and Qwen2.5-Coder

Three documented facts combine into a concrete risk. vLLM's `--generation-config` defaults to `auto`, which loads the generation config from the model path ([vLLM CLI reference](https://docs.vllm.ai/en/latest/cli/serve/)). Qwen2.5-Coder-7B-Instruct's `generation_config.json` sets `do_sample: true`, `temperature: 0.7`, `top_p: 0.8`, `top_k: 20` and **`repetition_penalty: 1.1`** ([Qwen generation config](https://huggingface.co/Qwen/Qwen2.5-Coder-7B-Instruct/raw/main/generation_config.json)). And vLLM "does not guarantee the reproducibility of the results by default", with reproducibility holding only on the same hardware and vLLM version ([vLLM reproducibility docs](https://docs.vllm.ai/en/latest/usage/reproducibility/)). The researchers' reading, which they did not test, is that a request setting only `temperature=0` still inherits the repetition penalty, a setting that penalises code for legitimately repeating identifiers. BigCodeBench separately warns that vLLM batch results vary across batch sizes and versions and recommends batch size 1 for more deterministic greedy output ([BigCodeBench README](https://github.com/bigcode-project/bigcodebench)). Temperature zero does not guarantee determinism for API models either ([Ouyang et al.](https://arxiv.org/html/2308.02828v2)). No published account documents this pitfall for Qwen2.5-Coder specifically.

Post-processing shifts scores too. BigCodeBench reports a separate "calibrated" pass@1 because models omit imports and setup code; the 0.8% and 0.3% average differences it cites should be re-checked in the paper ([BigCodeBench](https://arxiv.org/html/2406.15877)). For VA-RAG the extraction rule is more consequential than usual: when a response contains one block "for pandas 1.x" and one "for pandas 3", the choice of block flips the outcome class.

## What the evidence supports as best practice

Seven practices have support from more than one independent strand. First, act on version metadata outside the generator. Hard filtering on a trusted tag is the largest measured retrieval-side effect (55%→100% in VersionRAG with a strong model), displayed tags add under one F1 point, and relevance retrievers cannot separate versions ([VersionRAG](https://arxiv.org/html/2510.08109v1), [LibEvolutionEval](https://aclanthology.org/2025.naacl-long.348.pdf), [HoH](https://aclanthology.org/2025.acl-long.301.pdf)). Second, keep the context version-pure, including examples and scaffolding, because context determines which version's API is emitted and errors in context are copied and amplified ([Wang et al.](https://arxiv.org/html/2406.09834v3), [Ding et al.](https://arxiv.org/html/2306.03203)). Third, take the ask decision away from the small model and base it on explicit evidence, with a bias toward answering when asking cannot change the outcome ([APA](https://arxiv.org/html/2404.11972v3), [Zhang et al.](https://arxiv.org/html/2410.13788)). Fourth, verify output deterministically and at parameter level, flag only what can be attributed, and abstain otherwise ([Khati et al.](https://arxiv.org/html/2601.19106v1), [LibEvoBench](https://arxiv.org/html/2606.25402v1)). Fifth, repair once, with feedback that names the offending symbol and supplies the replacement with its signature and an example ([Wang et al.](https://arxiv.org/html/2406.09834), [CoCoGen](https://aclanthology.org/2024.findings-acl.138.pdf)). Sixth, when the conflict cannot be resolved, give each version's answer under its own label and never a merged block ([AmbigDocs](https://arxiv.org/html/2404.12447v3)). Seventh, evaluate by execution in pinned environments with a task-admission rule that proves the version matters, report both error directions of the asking policy, and state the minimum detectable effect ([CodeUpdateArena](https://arxiv.org/html/2407.06249v3), [Wen et al.](https://arxiv.org/html/2407.18418), [Miller](https://arxiv.org/pdf/2411.00640)).

Three widely used ideas lack support for this setting: always-on "mind the conflict" instructions, which degrade conflict-free cases in three benchmarks; contrastive decoding, which addresses a different conflict type; and whitelist-style constrained decoding for dynamically typed Python ([FaithEval](https://arxiv.org/html/2410.03727v3), [COIECD](https://arxiv.org/pdf/2402.11893), [Miranda-Pena et al.](https://arxiv.org/html/2604.07755v1)). The literature also predicts how VA-RAG's baselines will behave: the "mind the version" prompt should move little, and always-ask with a perfectly informed simulated user is closer to an oracle-version bound than to a deployable policy.

## Where VA-RAG is new and which prior work sits closest

Within what the researchers searched and opened, the joint setting is unstudied: no paper withholds the version, supplies retrieved chunks from two incompatible versions, scores a clarify-or-answer decision, and executes the answer in both environments. The pieces exist separately, and the closest work differs by facet.

| Facet of VA-RAG | Closest prior work | What it lacks relative to VA-RAG |
|---|---|---|
| Benchmark construction and scoring | [GitChameleon 2.0](https://arxiv.org/html/2507.12367v2) | Version is stated; one environment; no wrong-version class |
| Every answer run in every pinned environment | [quantum-api-drift](https://arxiv.org/html/2607.04072); [CodeUpdateArena](https://arxiv.org/html/2407.06249v3) UPass | Version or update is given; no retrieval conflict |
| Version not stated | [LibEvoBench](https://arxiv.org/html/2606.25402v1) L0/L1; [PinTrace](https://arxiv.org/html/2605.06279v1) | Static scoring, or measures the chosen pin and not correctness per environment |
| Mixed-version corpus | [VersionRAG](https://arxiv.org/html/2510.08109v1) | Question answering, version named in the query, no default when it is absent |
| Blending of old and new APIs | [Ashik et al.](https://arxiv.org/html/2604.09515v1); [AmbigDocs](https://arxiv.org/html/2404.12447v3) | 12.3% is a share of a failure subset under single-version docs; AmbigDocs is not code |
| Ask-when-unsure for code | [ClarifyCodeBench](https://arxiv.org/html/2607.00711); [HumanEvalComm](https://arxiv.org/html/2406.00215) | Library version is not an ambiguity category |
| Confidence-gated action | [CloudAPIBench DAG++](https://arxiv.org/html/2407.09726) | Gates retrieval, not a version commitment or a question |
| Version inference from code and errors | [SnifferDog](https://arxiv.org/abs/2103.02959); [Wang et al.](https://arxiv.org/html/2406.09834v3) detector | End-to-end "does it run" metrics; no accuracy for old-versus-new inference |
| Inventory-based output guard | [Khati et al.](https://arxiv.org/html/2601.19106v1) | Single version, curated samples, no receiver inference or keyword check |

Three contributions follow as defensible novelty claims: the benchmark combination itself; a measured blend rate for code generated from mixed-version chunks, which no paper reports; and accuracy figures for inferring a major version from context, which no tool reports. A calibrated probabilistic combiner of version evidence would be a smaller fourth, since the researchers found none in the Python ecosystem after a limited search. Each claim should be worded as "to our knowledge" given the search caveats above.

## Fourteen design changes, ranked by how much they protect the result

The ranking puts threats to the validity of every reported number first, then changes to the components most exposed by the evidence, then extensions. "Evidence-backed" means a cited measurement supports the mechanism of the change. "Author's inference" means the change is this review's or the researchers' design extrapolation without a direct test. Where a change mixes both, the label says which part is which.

| Priority | Change against the current design | Label |
|---|---|---|
| 1 | Pin and log the vLLM decoding configuration | Evidence-backed (facts); effect on scores is the author's inference |
| 2 | Admit tasks by a dual-reference matrix; split outcomes further | Evidence-backed |
| 3 | Break the gold-injection confound in retrieval | Evidence-backed |
| 4 | Extend the blend guard to keywords with receiver attribution | Evidence-backed (components); the combined rule is the author's inference |
| 5 | Repair the inventory and audit it against rule sets | Evidence-backed |
| 6 | Rebuild the regeneration step around a named replacement | Evidence-backed; acceptance check is the author's inference |
| 7 | Replace hand-set weights with tiered, calibrated evidence | Author's inference, built on evidence-backed components |
| 8 | Make asking cost-sensitive and report it as selective prediction | Evidence-backed (reporting); the exact rule is the author's inference |
| 9 | De-idealise and audit the simulated user | Evidence-backed (need); the specific arms are the author's inference |
| 10 | Turn the question into a closed choice with a fallback | Evidence-backed (options, fixed template); additions are the author's inference |

### 1. Pin and log the vLLM decoding configuration

The current design sets temperature 0 through vLLM. Start the server with `--generation-config vllm`, or send `repetition_penalty=1.0` explicitly in every request; record vLLM version, GPU type, batch size or concurrency, seed, max tokens, stop tokens and the rendered prompt after chat templating; and run a fixed subset twice to measure serving-side variation before attributing small differences to the system. The motivating facts are documented: the `auto` default loads the model's generation config, that config carries a 1.1 repetition penalty, vLLM is not reproducible by default, and batch size changes outputs ([vLLM CLI reference](https://docs.vllm.ai/en/latest/cli/serve/), [Qwen generation config](https://huggingface.co/Qwen/Qwen2.5-Coder-7B-Instruct/raw/main/generation_config.json), [vLLM reproducibility docs](https://docs.vllm.ai/en/latest/usage/reproducibility/), [BigCodeBench README](https://github.com/bigcode-project/bigcodebench)). Whether the default system prompt is injected when none is supplied was not verified and should be checked by rendering a prompt ([Qwen model card](https://huggingface.co/Qwen/Qwen2.5-Coder-7B-Instruct)). **Label: evidence-backed for the facts; that the penalty is inherited at temperature 0 and harms code is the author's inference and needs a direct test.**

### 2. Admit tasks by a dual-reference matrix and split the outcome classes

The four outcomes (target_only, portable, wrong_version, broken) are only meaningful if each task's tests discriminate by version. Admit a task only if the old-style reference passes in the old environment and fails in the new, the new-style reference does the reverse, and any portable reference passes both; run the matrix several times to catch flakiness. This is CodeUpdateArena's "pass new, fail old" rule and SWE-bench's fail-to-pass rule applied in the version dimension ([CodeUpdateArena](https://arxiv.org/html/2407.06249v3), [SWE-bench](https://arxiv.org/html/2310.06770v3)). Capture warnings and add a soft-fail class, as the Qiskit benchmark and VersiBCB's Strict/Lenient split do; this matters most for pydantic, where V1-style code runs on V2 with a `DeprecationWarning` and will otherwise be scored as cleanly portable ([quantum-api-drift](https://arxiv.org/html/2607.04072), [VersiBCB](https://arxiv.org/html/2601.12262v1), [Pydantic migration guide](https://pydantic.dev/docs/validation/latest/get-started/migration/)). Separate infrastructure failures (timeouts, out-of-memory, container start) from "broken" ([human-eval README](https://github.com/openai/human-eval)). Keep visible and hidden tests apart if any execution feedback is ever added ([arXiv PDF 2507.12367](https://arxiv.org/pdf/2507.12367)). **Label: evidence-backed.**

### 3. Break the gold-injection confound in retrieval

The current design always injects gold chunks from both versions plus BM25 distractors. That fixes three variables the conflict literature shows to be decisive. Vary chunks per version (1:1, 2:1, 1:2), because repetition overrides metadata and support imbalance costs single-prompt RAG up to 8% ([Schuster et al.](https://arxiv.org/html/2601.03746v3), [Wang et al.](https://arxiv.org/html/2504.13079v2)). Randomise or counterbalance which version comes first and report order sensitivity, because order alone moves 7B models by tens of points and Qwen2.5-7B has its own preferred order ([Xie et al.](https://arxiv.org/html/2305.13300v4), [HoH](https://aclanthology.org/2025.acl-long.301.pdf)). Report an end-to-end retrieval arm separately from gold injection, as AmbigDocs and HoH do; scores fall in that order, and BM25 over natural-language questions is weak on library documentation ([AmbigDocs](https://arxiv.org/html/2404.12447v3), [CodeRAG-Bench](https://arxiv.org/html/2406.14497)). Add conflict-free controls where both versions agree on the API, to measure over-asking and over-hedging. Condition results on closed-book correctness to separate "retrieval harmed a correct prior" from "retrieval failed to fix a wrong one", as the stale-document study does ([Ahmed et al.](https://arxiv.org/html/2609.31342)). **Label: evidence-backed.**

### 4. Extend the blend guard to keywords with receiver attribution

The current guard looks up called symbols in the diff. Version confusion concentrates in parameters, so store full signatures per version and bind each call's keywords against them ([LibEvoBench](https://arxiv.org/html/2606.25402v1), [Ashik et al.](https://arxiv.org/html/2604.09515v1), [Jain et al.](https://arxiv.org/html/2407.09726)). Attribute method calls to their owner by alias resolution and assignment tracking, the approach used by Wang et al.'s deprecated-API detector and PyCG ([Wang et al.](https://arxiv.org/html/2406.09834v3), [PyCG](https://ar5iv.labs.arxiv.org/html/2103.00587)). Flag only when the symbol or keyword is absent in the committed version and present in the other version's inventory, apply PCART's passing-style rules, and abstain on unresolved receivers and on `**kwargs` callables ([PCART](https://arxiv.org/html/2406.03839)). Generic names such as `.dict()`, `.json()`, `.append()` and `.copy()` collide with built-in types and will produce false positives under name-only matching; false positives are what turn repair loops harmful ([Chen et al., ACL 2025](https://aclanthology.org/2025.acl-long.881.pdf)). Use Ding et al.'s differential check so only violations introduced by the generation count ([Ding et al.](https://arxiv.org/html/2306.03203)). Then report guard precision and recall against the dual-environment execution oracle, since static methods have a recall ceiling well below 100% and no such figures exist for a version guard ([Miranda-Pena et al.](https://arxiv.org/html/2604.07755v1)). **Label: evidence-backed for each component; the combined decision rule is the author's inference.**

### 5. Repair the inventory and audit it against published rule sets

An `inspect` walk has known holes for exactly these libraries. Import NumPy's lazy submodules explicitly; do not key symbols by `__module__`; mark signatures that are `(*args, **kwargs)` or un-introspectable as "unknown", not "same" ([numpy/__init__.py](https://raw.githubusercontent.com/numpy/numpy/main/numpy/__init__.py), [pandas 3.0.0 what's new](https://pandas.pydata.org/docs/whatsnew/v3.0.0.html), [Python inspect docs](https://docs.python.org/3/library/inspect.html)). Add a fifth bucket, "present in both, deprecated in new", populated by recording warnings around attribute access and calls and from pydantic's `_migration.py`; without it the pydantic diff under-reports old-style usage ([pydantic/_migration.py](https://raw.githubusercontent.com/pydantic/pydantic/main/pydantic/_migration.py)). Audit recall against external lists, as AexPy does: every NPY201 name should land in old-only for NumPy 1.26.4 versus 2.x, and any miss is an extraction bug ([ruff rule docs](https://docs.astral.sh/ruff/rules/numpy2-deprecation/)). Cross-check the "changed" bucket against griffe (static-first) or AexPy (dynamic-first) and sample the disagreements ([griffe docs](https://mkdocstrings.github.io/griffe/guide/users/loading/), [AexPy README](https://github.com/StardustDL/aexpy)). Enter behaviour changes by hand, since about a fifth of post-upgrade failures are invisible to any signature diff ([PCREQ](https://arxiv.org/pdf/2508.02023)). **Label: evidence-backed.**

### 6. Rebuild the regeneration step around a named replacement

The current message names the offending calls. Add the committed-version replacement with its signature and one short example retrieved from the committed version's documentation, tied to the offending line, in a fresh prompt instead of an appended transcript. Naming the replacement fixed 95.5% of cases for CodeLlama-7b, whereas a bare deprecation notice was ignored by an 8B model in roughly three quarters of cases (the latter from an overview page; the two setups differ, so the contrast is suggestive) ([Wang et al.](https://arxiv.org/html/2406.09834), [Bae et al.](https://www.alphaxiv.org/abs/2510.19116)). Error plus retrieved context beats error alone ([CoCoGen](https://aclanthology.org/2024.findings-acl.138.pdf)). A fresh start outperformed continued debugging in one HumanEval study, an extrapolation to version repair ([Adnan & Kuhn](https://arxiv.org/html/2506.18403)). Because the model is served locally, test prefix forcing of the replacement symbol, which beat prompt-only repair on every open model reported; it was evaluated in line completion, not chat generation ([Wang et al.](https://arxiv.org/html/2406.09834)). Keep the one-round limit ([De-Hallucinator](https://arxiv.org/html/2401.01701)). Accept the regenerated output only if it passes the guard without new violations. **Label: evidence-backed for the message content and the single round; the acceptance check and the transfer of prefix forcing to chat output are the author's inference.**

### 7. Replace hand-set weights with tiered, calibrated evidence

Treat an exact pin and a library-authored migration string as constraints, not weighted votes, mirroring the constraint-based tools ([PCREQ](https://arxiv.org/pdf/2508.02023), [numpy/__init__.py](https://raw.githubusercontent.com/numpy/numpy/main/numpy/__init__.py)). For generic errors, take direction from looking the named symbol up in the inventory, not from the exception type, since backward and forward incompatibility are both common ([Huang et al.](https://ar5iv.labs.arxiv.org/html/2207.10347)). Score call sites, not symbols: a call that never passes the renamed keyword is evidence for neither version ([PCART](https://arxiv.org/html/2406.03839)). Give deprecated-but-working usage, such as pydantic `.dict()`, little weight, and treat `try/except` fallbacks and version checks as signs of portable code ([ruff source](https://raw.githubusercontent.com/astral-sh/ruff/main/crates/ruff_linter/src/rules/numpy/rules/numpy_2_0_deprecation.rs)). For the remaining soft evidence, fit log-likelihood ratios or a logistic regression on a development split, cap contributions per statement, and report calibration. Report the detector's accuracy by context type, and compare against a deterministic cascade (pin, then migration string, then majority of old-only versus new-only hits, then a prior). The user's own old-style code is simultaneously the best version signal and a primer that pulls the generator toward old APIs, so the same evidence should drive both inference and prompt scaffolding ([Wang et al.](https://arxiv.org/html/2406.09834v3)). **Label: author's inference; no tool uses a calibrated combiner, and no likelihood tables exist for these libraries. The components are evidence-backed.**

### 8. Make asking cost-sensitive and report it as selective prediction

Interpret the UNCERTAIN threshold as a cost ratio and sweep it, producing utility at two or three question costs in the manner of the VoI paper ([Dong et al.](https://arxiv.org/html/2601.06407v1)). Gate the question on whether the two versions' answers differ for the API in play; if the diff says "same", asking has no value. Tune thresholds on a development split and freeze them. Report ask precision and recall against a "needs clarification" label, the over-ask rate on version-stated and version-irrelevant controls, the wrong-version commit rate, risk-coverage and AUROC of the evidence score, and task success for never-ask, always-ask, oracle-version and the proposed policy ([Wen et al.](https://arxiv.org/html/2407.18418), [Zhang & Choi](https://arxiv.org/html/2311.09469)). The CONTEXT_CONFLICT state is well motivated, since contradiction is the category models least often ask about on their own ([ClarifyCoder](https://arxiv.org/html/2504.16331)). **Label: evidence-backed for the reporting package; the exact two-class VoI rule is the author's inference.**

### 9. De-idealise and audit the simulated user

Keep the rule-based oracle as the primary simulator, since a lookup that returns only a version string cannot leak the answer. Add three arms: a user who does not know, a user who gives a wrong or approximate version, and a user who can run a command or report an observed behaviour. Report results under each to bound the benefit of asking ([Lost in Simulation](https://arxiv.org/html/2601.17087v2), [Sim2Real](https://arxiv.org/abs/2603.11245)). Make the simulator answer only a version question about the right library and return a fixed "I don't have that information" otherwise ([Ambig-SWE](https://arxiv.org/html/2502.13069)). Run a control with the question removed or replaced by an irrelevant one and confirm downstream success does not improve, the check that exposed 32–41% false recovery in HumanEvalComm ([HumanEvalComm PDF](https://arxiv.org/pdf/2406.00215)). State in the paper that the always-knows result is an upper bound ([TiCoder](https://arxiv.org/html/2404.10100)). **Label: evidence-backed for the need and the audit; the three specific arms are the author's inference, and no study measures whether real developers know their installed version.**

### 10. Turn the question into a closed choice with a fallback

Keep the template fixed, which suits a 7B model ([APA](https://arxiv.org/html/2404.11972v3)). Make it specific: name the library, name the detected disagreement, and offer the two candidate versions as options ([Lee et al.](https://ar5iv.labs.arxiv.org/html/2305.13808), [Zamani et al.](https://ar5iv.arxiv.org/html/2006.00166)). Add a "not sure" option and a way to find out, such as `pip show pandas`. When the user does not know, fall back to one labelled answer per version, never a merged block ([AmbigDocs](https://arxiv.org/html/2404.12447v3)). **Label: evidence-backed for options and the fixed template, with the options evidence coming from web search and open-domain QA, not coding assistants; the "not sure" option, the command hint and the fallback ladder are the author's inference.**

### 11. Add the baselines the literature implies

Five comparisons are missing from the current set. A labelled two-branch answer with no question, the "complete answer" pattern, which costs no turn but risks mixing inside one response ([CondAmbigQA](https://arxiv.org/html/2502.01523)). "Assume the likelier version, state the assumption, give the one-line change for the other", the natural form of ties-favour-answering ([Zhang et al.](https://arxiv.org/html/2410.13788)). Per-version generation, one answer from each version's chunks, which follows from the single-document recall advantage ([AmbigDocs](https://arxiv.org/html/2404.12447v3)). A hard metadata filter with the oracle version, to separate inference error from generation error. And an execution self-debug arm in the true environment as an upper bound, since execution feedback is the strongest lever reported ([arXiv PDF 2507.12367](https://arxiv.org/pdf/2507.12367)). **Label: author's inference; no head-to-head of ask, answer-both and assume-and-state exists for code.**

### 12. Recompose chunks: signature, validated example, explicit validity boundary

Compose each chunk as fully qualified name, version tag, exact signature for that version, one short example, one-line description ([Jain et al.](https://arxiv.org/html/2407.09726), [Chen et al.](https://arxiv.org/pdf/2503.15231)). Run every indexed example through the guard against its tagged version before indexing, because a wrong API name in example code is the most damaging noise type for Qwen-7B and mis-tagged chunks turn the filter into a source of error ([Chen et al.](https://arxiv.org/pdf/2503.15231), [Ahmed et al.](https://arxiv.org/html/2609.31342)). Keep k at 3–5 and prize top-rank precision ([CodeRAG-Bench](https://arxiv.org/html/2406.14497)). Convert "changed in / removed in" facts into short rules instead of passing raw release notes, which lowered repair rates in DepRepair ([DepRepair](https://arxiv.org/html/2607.17957)). When both versions must be shown, state the boundary in the prompt ("X applies below 2.0; Y applies from 2.0") and balance the chunk counts ([Ahmed et al.](https://arxiv.org/html/2609.31342)). Consider restricting retrieval to APIs that differ between the versions, since retrieval for well-known unchanged APIs adds only distractors ([Jain et al.](https://arxiv.org/html/2407.09726)). **Label: evidence-backed; the explicit-boundary result is strong mainly for 70B-class models.**

### 13. Report power, small-sample intervals and sensitivity analyses

Keep the concept-clustered bootstrap, paired tests and Holm correction, and add four things. Publish the minimum-detectable-effect table so that null differences are not over-read, and estimate within-concept correlation from pilot data ([Miller](https://arxiv.org/pdf/2411.00640)). Use Wilson or Bayesian intervals at concept level alongside the bootstrap, and an exact McNemar test on paired binary outcomes ([Bowyer et al.](https://arxiv.org/html/2503.01747), [Dror et al.](https://aclanthology.org/P18-1128.pdf)). Analyse binary projections of the four-way outcome (target-correct, wrong-version, broken) and pre-register the primary contrasts. Use paraphrase or context-type variants as the instances within a concept and report the worst variant ([Mizrahi et al.](https://arxiv.org/html/2401.00595v3)). Fix one code-extraction rule, report the share of responses with several candidate blocks, and show raw versus import-calibrated scores ([BigCodeBench](https://arxiv.org/html/2406.15877)). Grow the number of concepts before anything else. **Label: evidence-backed; the MDE figures are the researchers' own calculation with an unsourced design-effect formula.**

### 14. Widen the benchmark: behavioural changes, realistic contexts, real questions

Label every concept with a change type and include a deliberate share of silent behaviour changes, with tests that assert on values and dtypes, not exceptions ([RustEvo²](https://arxiv.org/html/2503.16922v1), [GitChameleon v1](https://arxiv.org/html/2411.05830v1)). Mine the pandas 2.0 and 2.x notes as well as 3.0 for the 1.5.3→3.0 pair. Add pydantic files that legitimately mix `pydantic.v1` and V2 as a hard case for both CONTEXT_CONFLICT and the guard ([Pydantic migration guide](https://pydantic.dev/docs/validation/latest/get-started/migration/)). Break results down by clue type and weight the no-pin contexts, since over ninety percent of published notebooks state no dependencies ([SnifferDog](https://arxiv.org/abs/2103.02959)). Add a small tier of real Stack Overflow or GitHub questions selected by DS-1000-style criteria, with the true version established by reproducing the error in one environment and not the other, the labelling scheme of V2; expect a low yield, about 11% in one study ([DS-1000](https://ar5iv.labs.arxiv.org/html/2211.11501), [V2](https://arxiv.org/abs/1909.06251), [Wang et al., FSE 2023](https://2023.esec-fse.org/details/fse-2023-research-papers/80/-Remote-Compatibility-Issues-in-Deep-Learning-Systems-Problems-and-Opportunities)). Report each model's training cutoff, because pandas 3.0 material is recent. **Label: evidence-backed for the need; the two-tier design is the author's inference, and no version-labelled real-question dataset exists.**

## Conclusion

The literature changes what VA-RAG's central risk looks like. The design treats the hard problem as choosing between two documents, but the evidence says a 7B model's choice is governed by cues the system controls (chunk counts, order, the version dialect of the surrounding code) and that the residual errors live where the current guard does not look: keyword arguments, methods on untyped receivers, deprecated shims that still run, and behaviour changes with unchanged signatures. Pydantic is the sharpest example, because V1-style calls survive on V2 with a warning and so pass an existence diff, a blend guard and a "portable" test at once. The first measurement to make is therefore the guard's precision and recall against the dual-environment oracle, since no published work reports one.

The second shift concerns the claim VA-RAG can make. With 60 concepts the benchmark supports statements about differences of ten points or more, and the always-informed simulated user makes the asking result an upper bound. A paper that reports the minimum detectable effect, a "user does not know" arm, order and ratio sensitivity, and a verified decoding configuration is making a smaller claim than "version-aware RAG works", and one the evidence base cannot yet contradict: that for an unstated version and mixed documentation, rule-based inference plus a hard filter and a parameter-level guard beat prompt-level awareness by a margin large enough to see.
